# TXW935003B（ICNL9707）屏调试记录

> 配套文档：`doc/USB-CDC调试固件使用说明.md`（CDC 虚拟串口用法）。
> 本文记录 9.35" 2192 玻璃条形屏的调试过程、已确认现象与最终判定。

## 一、屏与平台

| 项 | 值 |
|---|---|
| 面板 | TXW935003B（TXW，9.35" 条形屏） |
| Driver IC | ICNL9707（候选，无 vendor datasheet） |
| 玻璃分辨率 | **440 × 1920**（驱动头文件第 16 行注明） |
| SoC | ArtInChip D133 |
| 接口 | MIPI DSI，4-lane，burst video mode，RGB888 |
| 调试固件 | `images/d133-txw935003b-cdc.img`（USB CDC 虚拟串口，COM4） |

## 二、关键结论（先看这个）

1. **面板玻璃宽度是 440，不是 480。** 修 480→440 解决了"满屏黑白竖纹"，但那只是**部分**根因。**行宽实验（本节末第九节）证明滚动白带对行宽 440→720 **完全不变**，因此"每行字节数与面板采样宽度差"**不是**当前滚动带的根因，方向已排除。
2. **开机必须设置 COLMOD = RGB888（0x3A 0x77）。** 初始化序列缺这条则开机黑屏，手动发 `dispdbg cmd 0x3A 0x77` 才亮。此修复已固化进驱动。
3. **越权禁用面板 BIST 自测。** 驱动默认 `TXW_PANEL_BIST=1`，会把自己停在自测颜色条上、盖掉 framebuffer；CDC 调试固件与最终驱动均需 `TXW_PANEL_BIST=0`。
4. **`dispdbg set` / `dispdbg reset` 的二次初始化曾会永久黑屏，只能重新上电恢复。** 属 reload 流程 bug；当前 `drv_fb.c` 的 `dispdbg_reload()` 已补二次 `aicfb_update_layer()`（时钟门控后恢复 UI 层 buffer 关联）并在代码注释里说明修复。**结论 4 已确认修复（2026-10 真机验证）**——`dispdbg set` / `dispdbg res` / `dispdbg reset` 在线扫参、反复 reload 均不再黑屏，可放开在线调整、免重烧。

## 三、已验证现象与判断

| 现象 | 判定 |
|---|---|
| `dispdbg pattern 1`（全白）后屏幕从蓝变白 | DE → DSI 数据通道**工作正常**，屏未死 |
| `dispdbg pattern 2`（纯黑）/ `3`（纯红）底色正确、但叠加**滚动的竖线/白带** | 竖线**不是 DE 数据内容**，是叠加的传输层/面板层干扰 |
| C2 RSO 改 600→720（`dispdbg cmd 0xC2 0x30 0xC0`）后色带**明显变清晰** | 面板内部水平采样更贴近 720 RGB 档，RSO 600（默认）偏低 |
| 纯色下竖线**周期性"关窗"式白带滚动** | 每行 DSI 发送字节数 ≠ 面板期望行宽，逐行累积欠/多数据，产生追赶带 |

**推断**：玻璃是 440 宽，但 ICNL9707 源极驱动很可能按**更高的水平分辨率档（约 720 RGB）**逐行采样。DE/DSI 目前每行只发 440 像素，行内数据不足，导致滚动白带与竖线。下一步方向：把 DE 与 DSI 的行宽提高到面板匹配值（如 720），或用面板内部寄存器对齐。

## 五、已做的代码修改

### 1. `variants.json` — `d133-txw935003b` 时序
重现 `d133-txw935003b-cdc` 的验证结果：宽度 480→**440**，`hfp=20, hbp=20`，重建 `pixelclock`（htotal×vtotal×60）。

### 2. `panel_dsi_icnl9707_txw935003b.c` — 开机亮屏 + 关 BIST
- `TXW_PANEL_BIST` 默认 1→**0**（禁用面板自测，避免盖掉 framebuffer）。
- 在写 F0/F1 关扩展命令窗口之后、`sleep-out` 之前，插入：
  ```c
  ret = mipi_dsi_dcs_send(panel, (u8[]){ 0x3A, 0x77 }, 2);  /* COLMOD = RGB888 */
  ```
  开机即设对像素格式，不再黑屏。（注：无现成 `mipi_dsi_dcs_set_pixel_format`，用 `mipi_dsi_dcs_send` 直发。）

### 3. `drv_fb.c` — `dispdbg_reload()` 修复（DE 层 buffer 关联）
`aicfb_enable_panel(ON)` 之后再补一次 `aicfb_update_layer()`，否则时钟门控后 UI 层 buffer 关联丢失，reload 后屏幕永久黑。（已修，但 reload 本身对 TXW 仍有二次初始化黑屏问题，见下。）

## 六、遗留问题

1. **滚动竖线/"关窗"白带**：根因指向 DE/DSI 行宽(440) 与面板内部水平采样档(疑似 ~720)不匹配。**待验证**：将 DE + `DSI_VID_PKG_SIZE` + C2 RSO 统一提高行宽，看是否消除滚动带。
2. **`dispdbg set/reset` 二次初始化黑屏**：已修复（见结论 4，2026-10 真机验证），在线扫参可正常进行。
3. **`TXW_TEST_WIDTH` 仍为 480**（仅诊断打印用，不影响实际时序；可顺手改 440 消除误导）。
4. **无 vendor datasheet**：C2 RSO 档位、行时序寄存器含义来自 Milk-V/CVI ICN9707 参考，不能 100% 确定匹配 TXW 玻璃。

## 七、下一步建议（按优先级）

1. **验证行宽不匹配假设**：编译一个 DE width=720 + `DSI_VID_PKG_SIZE=720` + C2 RSO=720 的测试固件，观察滚动白带是否消失（玻璃物理 440 列会显示 720 数据的前 440 或折叠效果，属预期）。
2. 若 720 正确，把最终参数固化进 `d133-txw935003b`（非 CDC）正式固件。
3. 修复 `dispdbg reload` 二次初始化黑屏。
4. 将 `TXW_TEST_WIDTH` 改 440，更新驱动头文件注释说明 440 vs 480 来历。

## 八、实验代价提醒

- 所有 `dispdbg set xxx`（pclk/hfp/hbp/hsync/.../assign/polrs/fmt/res）都会触发 `dispdbg_reload()`。**reload 黑屏 bug 已修复（2026-10 真机验证），在线扫参安全**，无需重新上电。
- `dispdbg cmd xxx` 只切命令模式发一条 DCS 再切回，**不触发 reload，安全**。在线调面板侧寄存器（如 C2、0x3A）用它。
- `dispdbg pattern 0-6` 只写 framebuffer，**安全**，用于判 DE 数据正确性。

## 九、行宽实验固件（720 验证，已编译待上板）

目标：验证"面板内部按 ~720 RGB 档逐行采样"假设（第六节遗留问题 1）。

**方法**：新增调试变体 `d133-txw935003b-cdc-720`，把 host 三处行参数统一提到 720——

| 项 | 440(当前 CDC) | 720(实验) |
|---|---|---|
| `FIRMWARE_WIDTH`（DE 行宽 + `DSI_VID_PKG_SIZE`，`aic_hal_dsi.c:312` 同源） | 440 | 720 |
| C2 RSO（驱动 `TXW_TEST_C2_HI`，按 `FIRMWARE_WIDTH` 编译期推导） | 600(0x31) | 720(0x30) |
| `pixelclock`（htotal×vtotal×60） | 57.15 MHz | 90.21 MHz |
| DSI lane rate（pclk×24/4） | ~343 Mbps | ~541 Mbps |

`DSI_VID_PKG_SIZE` 无独立宏，直接读 `timing->hactive`（`aic_hal_dsi.c:312`），因此改 `FIRMWARE_WIDTH` 即同时改了 DE 采样宽度与 DSI 每行包字节数。C2 RSO 在驱动内按 `#if FIRMWARE_WIDTH == 720` 推导为 0x30（720 RGB），其余宽度默认 0x31（600）；C2_LO=0xC0（NL=0x3c0）不变。

**产物**：`images/d133-txw935003b-cdc-720.img`（29.3 MB，已核验宏 `FIRMWARE_WIDTH=720`、`FIRMWARE_PIXELCLOCK=90213120`，驱动对象内 C2 命令字节为 `0x30 0xC0`）。

**上板验证判据**：
1. 刷入后 `dispdbg info` 应显示 `active 720x1920  pclk 90213120`。
2. 全白(`pattern 1`)/纯黑(`pattern 2`)下，期待滚动竖线/"关窗"白带**消失或显著减弱**（玻璃物理 440 列只显示 720 数据的前 440 或折叠，属预期）。
3. 若滚动带仍在但形态变化，说明行宽假设部分成立，可再用 `dispdbg cmd 0xC2 0x30 0xC0`（安全）对比其他 RSO 档在线微调。
4. 若 720 正确，把相同参数固化进正式变体 `d133-txw935003b`（第七节下一步 2）。

> 注意：`FIRMWARE_WIDTH==720` 的 C2 推导也作用于正式 `d133-txw935003b` 变体（同一驱动源）。正式变体当前 width=480，走的是"否则"分支 RSO=600，不受影响。正式固件如需 720，需同步把其 width 改成 720。

## 十、720 实测结果（重要：行宽假设被排除）

**结果**：刷入 `d133-txw935003b-cdc-720.img`，`dispdbg info` 确认 `active 720x1920  pclk 90213120`（固件生效），**滚动白带与 440 固件完全一模一样**。

**结论**：
1. **行宽假设（DE/DSI 行宽 = 面板内部采样宽度，第六节 1）被排除。** 若面板按 ~720 RGB 采样，host 每行从 440 加到 720 应至少改变滚动带的频率/相位；实测不变 → 滚动带**与每行像素数无关**。
2. 滚动带是**逐行字节数无关**的叠加干扰，方向收敛到两类：
   - **A 垂直扫描 slip**：面板内部行计数期望的 vtotal 与 host 每帧发射的 vtotal（1968）不符，逐帧漂移，形成缓速滚动带。行宽无关、vporch 相关。
   - **B 像素时钟拍频**：host DSI pclk 与面板内部采样时钟之间存在拍频，产生随 pclk 变化的滚动带。行宽无关、pclk 相关。
   - （C DE 带宽/FIFO 饥饿基本排除：720 数据率近翻倍（343→541 Mbps/lane）现象却不变。）
3. `dispdbg cmd 0xC2 0x30 0xC0` 在线改 RSO=720（记录第三节）"变清晰"发生在 440 行宽下；720 固件已内含 RSO=720 仍与基线"完全一样" → 基线本就是 RSO=720，**RSO 也不是驱动项**。

**deciding 实验（A vs B，用 `dispdbg set`，reload 已修则免重烧）**：
- **试 A-vertical**：`dispdbg set vbp 60`（或 vfp/vsync），观察滚动带**滚动速度/密度**是否随 vtotal 变化。变了 → slip 假设成立，收敛出"冻结"滚动带的 vtotal。
- **试 B-clock**：`dispdbg set pclk 85000000`（约 -6%）再 `dispdbg set pclk 96000000`（约 +6%），观察滚动带速度是否随 pclk 走。随 → 拍频假设成立。
- 若两者都不影响 → 需另查（面板命令表里是否有显式扫描/行时序寄存器需与 host 对齐，无 datasheet 时按 Milk-V/CVI 参考逐条试）。

> reload 风险：若 `dispdbg set` 某步造成永久黑屏，重新上电即恢复；这也顺带验证结论 4 是否已修复。

> ### 实测追加（2026-10，判定实验进行中）
> reload 已确认修复，可在线扫参。
> - `dispdbg set vbp 12`（空改动）无明显变化。
> - `dispdbg set vbp 60`（vtotal 1968→2016）出现**规则闪烁**——垂直方向对 vbp 有反应但表现为闪烁而非色带移动，方向 A（vtotal slip）需结合纯色判别进一步收敛。
> - 纯色测试（白/黑/红/蓝/绿）下**四周出现一圈补色边框**（红界面四周青、绿界面四周品红、黑界面四周白……），且**运动的竖线在纯色下也存在（与数据内容无关）**。
> - 显式 `0x2A/0x2B/0x36`（CASET/RASET/MADCTL）+ COLMOD(`0x3A 0x77`) 均无效，边框不变 → 与之前 720 行宽实验一致：**host 端窗口/行宽/格式类参数都碰不到这个边框与竖线**，指向更底层面板行为。
> - **新线索：`pattern 3`（纯红 255,0,0）显示为绿色** → 疑似 RGB 通道重排，lane assign / 数据映射成为待查高嫌疑。
> - **pclk 判定实验（2026-10）：`dispdbg set pclk 54000000` / `60000000`（±5%）竖线完全不变** → 排除时钟拍频（方向 B）。结合此前已排除的 hactive 行宽（720 不变）、CASET/RASET/MADCTL、COLMOD、vtotal，**竖线完全不受 host 时序/时钟参数影响、且与数据内容无关（纯色下也在）** → 收敛指向 **lane 物理映射（assign/polrs）或面板内部源极驱动配置（初始化序列 C1/C2 等）**。

> - **重大参考发现（2026-10）：** 用户提供 `panel-clockwork-cwd686.c`（ClockworkPi / Feb 2021，Linux DRM ICNL9707 成熟量产驱动）。给出：

>   - 用户选定**方案 A**：新建基于 cwd686 完整 init + MADCTL 的 ArtInChip 面板驱动并编译测试固件。**待确认**屏物理行数（480×1280 逻辑 vs 440×1920 现有猜测）后定 timing。
