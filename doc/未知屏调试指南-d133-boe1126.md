# D133-BOE1126 未知屏点亮调试指南

## 一、当前状态与现象分析

### 照片现象
屏幕整体呈横向彩色条纹 + 斜向彩噪 + 竖线撕裂，画面结构可辨认但不是正确图像。

### 关键结论（基于代码链路核实）
1. **当前显示的不是"屏幕自带待机界面"**。本工程固件上电默认画面是 `AIC_DISP_COLOR_BLOCK` 色块测试图：5 色（蓝/绿/红/黑/白）100×100 像素棋盘格，见 `bsp/artinchip/drv/display/drv_fb_helper.c` 的 `fb_color_block()`。照片中红绿蓝大色块交替的结构与它吻合。
2. **这说明点亮链路大部分已通**：DSI 高速传输在工作、初始化序列被面板接受（否则会黑屏或白屏），但图像内容被破坏 → 典型的"参数不匹配"而非"完全不通"。
3. 破坏模式（斜条纹 + 竖线撕裂 + 彩色噪点）指向以下嫌疑，按概率排序：
   - **分辨率/时序不匹配**：真实屏不是 440×1920，行宽对不上导致斜切撕裂
   - **lane 顺序/极性**：板级注释标明此板 lane 反接（assign=0x123），若未知屏走线不同则数据错位
   - **DSI 比特率裕量不足**：lane rate 由 pixelclock 推导（`aic_hal_dsi.c`），4 lane RGB888@65.856MHz ≈ 395Mbps/lane，若面板要求更高或更低会误码
   - **初始化序列不匹配**：序列来自 FL7707N+BOE11.26 的 V5.5 文档（见驱动头注释），不同批次/变体面板 gamma、porch 寄存器可能不同

## 二、新增在线调试命令 `dispdbg`

已在 `bsp/artinchip/drv/display/drv_fb.c` 末尾新增 msh 命令（RT-Thread 控制台 `aic>` 提示符下使用），**改参数无需重新烧录**：

| 命令 | 功能 |
|---|---|
| `dispdbg info` | 打印当前生效的时序/DSI/fb 参数，含换算出的 fps |
| `dispdbg set <key> <value>` | 在线修改并自动重启面板。key 支持：`pclk` `hfp` `hbp` `hsync` `vfp` `vbp` `vsync` `fps`（按 htotal×vtotal×fps 重算 pclk）`lane` `assign`（十进制或 0x 前缀）`polrs` `fmt`（0=RGB888 1=RGB666L 2=RGB666 3=RGB565） |
| `dispdbg res <w> <h>` | 在线改分辨率，按 60Hz 自动重算 pclk，并同步 width/height/stride/fb_size；超过已分配 framebuffer 会拒绝执行 |
| `dispdbg cmd <c> [p...]` | 运行时发送任意 DCS 命令，自动切 command 模式发完再切回 video，如 `cmd 0x3a 0x77`（COLMOD）、`cmd 0x36 0x00`（MADCTL） |
| `dispdbg pattern <id>` | 填充测试图：0 五色棋盘 1 全白 2 全黑 3 红 4 绿 5 蓝 6 水平灰阶 7 垂直灰阶 |
| `dispdbg read <cmd>` | ⚠️ **不可用于读屏 ID**，见下方说明 |
| `dispdbg reset` | 用当前内存参数重新初始化面板（OFF→50ms→ON，含完整 init 序列） |

生效原理：DE 与 DSI 驱动都从 `panel->timings` 同一结构体指针取参（`drv_de_core.c:246` / `panel_dsi.c:125`），改内存值后面板 OFF/ON 一轮即全部重载。`cmd` 子命令则必须在发送前后切换视频模式——`aic_dsi_send_cmd()` 本身不动视频模式配置，面板驱动能生效是靠 `panel_dsi_send_perpare()` 先切到 command 模式（`drv_dsi.c:270`/`283`），不照做命令会被静默丢弃。

### ⚠️ 读屏 ID —— 早期结论（已修复，见下方更新）
> **更新**：DSI 回包读取已实现（`aic_hal_dsi.c` 新增 `dsi_cmd_rd()`，`drv_dsi.c` 的 `aic_dsi_read_cmd()` 改从 RX FIFO 读回，面板驱动 `txw_read_dcs` 接上 `di_read_cmd` 回调），`dispdbg read` 现在读的是**面板回包 FIFO** 而非发送 payload 寄存器。以下历史记录是修复前的诊断结论，仅作存档。

早期核实源码后曾判定 `dispdbg read` **无法读到面板 ID**：

- 旧 `aic_dsi_read_cmd()`（`drv_dsi.c:301-308`）发送 `MIPI_DSI_DCS_READ` 后回读的是 `DSI_GEN_PD_CFG`；
- 而 `DSI_GEN_PD_CFG` 在 `dsi_cmd_wr()` 中是**发送用的 payload 寄存器**（`aic_hal_dsi.c:431-434` 往里写数据）；
- 该 DSI 控制器驱动当时**没有实现回包 FIFO 读取**。

因此修复前实测读到的 `0x04→0x38`、`0xDA→0x38`、`0xDB→0x21`、`0xDC→0x1F` 全是芯片寄存器残留值，**不代表面板身份**。

替代识别手段（按成本排序）：
1. **拆机看 FPC 丝印与驱动 IC 型号**——最快最准，拿到型号即可查 spec 得到正确分辨率/porch/init 序列；
2. **参数扫描法**——用下方第 2 步 A/B 的组合试验反推面板期望的格式、分辨率与 lane 配置；
3. **联系屏厂/供应商索要 spec**——若能提供采购渠道信息。

## 三、调试步骤（按序执行）

### 第 1 步：确认基线
```
dispdbg info        # 核对与上表一致
dispdbg pattern 1   # 全白
dispdbg pattern 2   # 全黑
```
- 全白/全黑能干净切换 → 数据通路基本健康，重点查分辨率/lane
- 纯色屏仍带噪点/条纹 → DSI 物理层问题（lane 顺序、极性、速率）优先

### 实测进展记录（2026-10）

**颜色真值表**（亮度不均匀，屏上半黑/下半亮带，颜色观测受污染）：

| 发送 pattern | 期望 | 实际 |
|---|---|---|
| 2 全黑 | 黑 | 偏白 |
| 1 全白 | 白 | 偏绿 |
| 3 全红 | 红 | 偏黄 |
| 4 全绿 | 绿 | 偏紫 |
| 5 全蓝 | 蓝 | 偏青 |
| 6 水平灰阶 | 渐变 | 偏黑 |
| 7 垂直灰阶 | 渐变 | 偏黑 |

结论：**流确实到达面板并影响显示**（颜色随 pattern 变化），但数据解释错误 + 垂直扫描窗口只对上一部分（上黑下亮）。

**两个已核实的硬事实（影响调试路径）**：
1. ~~`dispdbg read` 读不到面板 ID~~ → **已修复**：新增 `dsi_cmd_rd()`（RX FIFO 读回）+ `aic_dsi_read_cmd()` 改用之，`dispdbg read` 返回面板回包低 24bit；之前读到的 0x38/0x21/0x1F 是修复前残留值。识别屏幕仍建议参数扫描/拆机，但 DCS 读回已可诊断面板内部寄存器。
2. 初始化序列**从未发送 0x3A (COLMOD)**，也从未设置 0x2A/0x2B (CASET/RASET) 显示窗口——面板的像素格式和扫描窗口全靠内部默认值，与 SoC 发出的 RGB888 流可能不一致。这是"跨通道偏色"的头号嫌疑。

**新增调试能力**（已编入固件，无需重烧即可实验）：
```
dispdbg cmd <c> [p...]      # 运行时发任意 DCS 命令（自动切 cmd 模式再切回 video）
dispdbg res <w> <h>         # 运行时改分辨率（带 fb 越界保护，自动重算 pclk 保持 60Hz）
dispdbg set fmt <0-3>       # 切 SoC 输出格式 0=RGB888 1=RGB666L 2=RGB666 3=RGB565
```

### ★ 突破：反色已确认并固化（A1 试验结果）

这块屏是**反相面板**，`dispdbg cmd 0x21`（DCS ENTER_INVERT_MODE）验证有效：
- 发 `0x21` 后，`pattern 2`（全黑）显示为**整体黑色**（此前偏白）；
- `pattern 1`（全白）显示为**白色**。
- 双重取反抵消后极性正确 → **`0x21` 是这块屏需要的修复**。

已把 `0x21` 写入 `panel_dsi_fl7707_boe1126_b.c` 的 init 序列（exit sleep 之后、display on 之前），开机默认极性即正确，无需再手动发命令。

两个观察的正确解读（都不是故障）：
1. **"缓慢变白"是填充耗时，不是液晶响应慢**。`dispdbg pattern` 用 CPU 逐像素软件填充 framebuffer（440×1920×3 ≈ 2.5MB）再 cache clean，在 480MHz 上要数百毫秒~1 秒；DE 实时扫描 fb，所以看到"边填边显示"的渐变。可排除电源/gamma 嫌疑。
2. **"两侧白色竖线"是新线索**。`pattern 2` 全黑时中间正确显黑、两侧出现白竖线（反色下白=数据255），说明两侧那几列落在 porch/未覆盖区域而非 active 数据 → **hactive 440 与面板真实宽度可能不完全匹配**（面板 active 或略宽，边缘吃到了 porch）。下一步用 `dispdbg res` 微调宽度 + `set hfp/hbp` 验证。

### 第 2 步 A：反色/格式/方向快速试验（新，优先做）

**A1. 反色试验**（全黑显示成偏白是反色的典型特征，成本最低先试）：
```
dispdbg pattern 2      # 记住当前状态
dispdbg cmd 0x21       # ENTER_INVERT_MODE
dispdbg pattern 2      # 黑变黑？
dispdbg pattern 1      # 白变白？
dispdbg cmd 0x20       # EXIT_INVERT_MODE 恢复
```

**A2. COLMOD 像素格式试验**（面板从未被告知格式）：
```
dispdbg cmd 0x3a 0x77  # 声明 24bpp RGB888（与当前 SoC 输出一致）
dispdbg pattern 3      # 红是否变干净？
dispdbg set fmt 3      # SoC 侧切 RGB565
dispdbg cmd 0x3a 0x55  # 面板侧声明 16bpp RGB565
dispdbg pattern 3
dispdbg set fmt 0      # 恢复 RGB888
dispdbg cmd 0x3a 0x77
```
哪一组出现**干净纯色**（哪怕亮度带仍不均匀），哪组就是正确格式。

**A3. 显示窗口/扫描方向试验**：
```
dispdbg cmd 0x36 0x00  # MADCTL 默认
dispdbg pattern 6
dispdbg cmd 0x36 0x20  # MV 位：X/Y 交换
dispdbg pattern 6
dispdbg cmd 0x2b 0x00 0x00 0x07 0x7f  # RASET 0..1919（显式设窗口）
dispdbg cmd 0x2a 0x00 0x00 0x01 0xb7  # CASET 0..439
dispdbg pattern 1
```

**A4. 分辨率互换试验**（440×1920 与 1920×440 像素数相同，fb 够用）：
```
dispdbg res 1920 440
dispdbg pattern 6      # 看渐变方向与均匀度
dispdbg res 440 1920   # 恢复
```

### 第 2 步 B：排查 lane 配置
```
dispdbg set assign 0x321   # 恢复正序，看是否改善
dispdbg set polrs 0xFFFF   # 极性全翻转试探（每 lane 2bit，按 4 lane 组合试）
dispdbg set lane 2         # 降 2 lane 试探（速率减半，抗误码能力增强）
```
每改一项自动重启面板，拍照记录。若 `assign 0x321` 下出现"正确图案但通道错乱"（如红绿互换、镜像），即可反推真实走线。

### 第 3 步：排查分辨率/时序
未知屏最常见是 hactive/vactive 与真实不符。**hactive/vactive 是编译期宏（FIRMWARE_WIDTH/HEIGHT），dispdbg 不改它们**，需要改 `variants.json` 重编（见第四节）。但可以先用 dispdbg 试 porch：
```
dispdbg set hfp 20
dispdbg set hbp 20
dispdbg set hsync 4
dispdbg set vfp 12
dispdbg set vbp 12
dispdbg set vsync 4
dispdbg set fps 50        # 降帧率试探（pclk 随之降低，lane rate 下降）
```
斜纹角度随 porch 变化而变 → 确认是行时序不匹配；斜纹消失但图像拉伸/压缩 → hactive/vactive 不对，进入第 4 步。

### 第 4 步：改分辨率重编（编译期参数）
编辑 `E:\001\AIC-BarDisplay-main\variants.json` 中 `d133-boe1126.timing` 的 `width/height`，并按 `pixelclock = (w+hfp+hbp+hsync) × (h+vhfp+vbp+vsync) × fps` 重算 `pixelclock`，然后：
```
cd E:\001\AIC-BarDisplay-main
.\build.cmd d133-boe1126
```
产物：`images\d133-boe1126.img`（烧录 NOR）。

### 第 5 步：初始化序列差异
若时序/lane 都正确仍花屏，对比面板 spec 与驱动中 init 序列（`panel_dsi_fl7707_boe1126_b.c:53-102`）。重点寄存器：
- `0xB2`（显示控制，含 porch/同步极性相关位）
- `0xC0/C1`（电源与时序参数）
- `0xE9/0xEA`（gamma 相关，序列最长、批次差异最大）
- `0xB9`（解锁命令，F1 12 87 为 FL7707N 标准解锁字）
不同批次面板可能需要不同版本序列，需向屏厂索取对应 spec。

## 四、决策树速查（已按实测更新）

当前状态：**流已到面板但颜色错乱 + 亮度上黑下亮（垂直窗口只部分匹配）**。读 ID 已确认不可用，改走"发命令 + 扫参数"路线。

```
先做第 2 步 A（成本最低，命中率高）：
A1 反色 cmd 0x21 → 全黑变黑、全白变白?
├─ 是 → 面板反色，init 序列补 0x20/0x21 即可
└─ 否 → A2 像素格式：cmd 0x3a 0x77 / set fmt 组合
        ├─ 出现干净纯色 → 格式不匹配已定位
        └─ 仍乱 → A3 方向 cmd 0x36 + 显式 CASET/RASET
                └─ A4 分辨率互换 res 1920 440 / res 440 1920

颜色已对但仍上黑下亮/不铺满 → 垂直时序窗口问题：
├─ 扫 vfp/vbp/vsync（第 3 步），观察亮带位置是否移动
└─ res 试真实分辨率（若 A4 已发现方向反了，用正确方向的 w/h）

颜色乱 + 细竖纹/斜纹 → 物理层：assign/polrs/lane（第 2 步 B）
```
