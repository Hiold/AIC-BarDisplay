# 横屏显示改造说明（landscape-mode 分支）

> 目标：把原有「竖条副屏」的全部固件变体改为**横屏显示（内容旋转展示横屏）**。

## 一、设计思路

这些副屏面板**硬件本身是竖条屏**（物理上宽 < 高，例如 `440×1920`、`320×1280`）。
所谓「横屏」不是改面板物理方向，而是**把内容旋转 90°，让长边（1920）在屏幕上水平展示**，
即最终效果等价于「内容为横屏、面板横放使用」。

在本应用（usbdisp 副屏 + 独立 UI 窗口 + DE 视频层）里，屏幕扫描仍是竖条（DE/DSI 时序不变），
因此旋转由三个互相独立的环节协作完成：

| 环节 | 职责 | 现状 → 改造 |
| --- | --- | --- |
| 分辨率 / 能力声明 | `udisp_screen` 上报为横屏（宽>高），USB 能力串 `R<宽>x<高>`、HID、RX 校验随之横屏 | 启用 fb 旋转 `AIC_FB_ROTATE_DEGREE=90` |
| 视频（VE/JPEG 硬解） | 把横屏 JPEG 帧解码旋转成竖条扫描布局 | `AIC_USB_DISP_ROTATION_FULLSCREEN` + `MPP_DEC_INIT_CMD_SET_ROT_FLIP_FLAG` |
| UI（LVGL 窗口） | UI 窗口定位到物理（竖条）扫描屏，避免随旋转漂移出屏 | `ui.c` 用 `FIRMWARE_WIDTH/HEIGHT` 定位 |
| 资源（video.bin） | 空闲视频由竖屏重编码为横屏 | `tools/video_rebuild/rebuild.py --rotate 90` |

## 二、改动清单

### 1. 配置头 `firmware/configs/*.h`（全部 13 个 display 变体）
- `#define AICFB_ROTATE_0` → `#define AICFB_ROTATE_90`
- `#define AIC_FB_ROTATE_DEGREE 0` → `90`，并新增 `#define AIC_FB_ROTATE_EN 1`
  - 作用：`aicfb_fb_info_setup()` 交换 active 宽高 → `udisp_screen` 上报横屏，
    `AICFB_GET_SCREENINFO`（drv_fb.c:133-146）、LVGL `lv_port_disp`、USB 能力串/HID/RX 全部自动变为横屏。
- app 类变体（usbdisp / dash / test）新增 `#define AIC_USB_DISP_ROTATION_FULLSCREEN 1`
  - 作用：打开 MJPEG 解码器的旋转 stride 布局（mjpeg_decoder.c:601），供 VE 旋转。
- 注：bootloader 配置（`*_bootloader*.h`）未改。

### 2. 应用 `application/rt-thread/usbdisp/display.c`
- `udisp_decoder_open()`：在打开 MJPEG 解码器后，通过 `MPP_DEC_INIT_CMD_SET_ROT_FLIP_FLAG`
  设置 `rotmir = MPP_ROTATION_90`（受 `AIC_USB_DISP_ROTATION_FULLSCREEN` 门控）。
- `udisp_decode()`：把视频层 crop/pos/scale 的参考尺寸从 `udisp_screen`（现为横屏）改为
  **物理扫描屏** `FIRMWARE_WIDTH × FIRMWARE_HEIGHT`（竖条）。
  - 因为解码器旋转后 NV12 是竖条布局，要放在竖条屏幕上铺满，需用横屏 `udisp_screen`（仅对 USB 上报）之外的物理尺寸。
  - 原生像素门控、居中裁剪、层定位全部改用 `scanout_w/h`。

### 3. 应用 `application/rt-thread/usbdisp/ui.c`
- `ui_layer.pos` 改按 `FIRMWARE_WIDTH/HEIGHT`（物理竖条扫描屏）居中定位，避免 UI 窗口随 fb 旋转在窄边上越界。
- `ui_pick_canvas()` 在横屏（`width>height`）时走「宽屏」分支（400×480），满足内存约束。

### 4. 视频资源（横屏重编码）
- `application/rt-thread/usbdisp/assets/video/video.bin`
  - 由原 `480×1920` 旋转 90° 重编码为 **1920×480**（602 帧、~25.7MB、quality 33）。
  - 元数据 `application/rt-thread/usbdisp/assets/video/video.json` 已同步（含 `rotate:90`、`orientation:landscape`）。
- `application/rt-thread/usbdisp/assets_av093x/video/video.bin`
  - 由原 `480×1920` 旋转 90° 再居中裁剪为 **1280×320**（~12.5MB）。
  - 元数据 `assets_av093x/video/video.json` 已同步。
- 工具 `tools/video_rebuild/rebuild.py`：新增 `--rotate {0,90,180,270}`，
  可在裁剪前把源帧旋转指定角度，生成横屏 LVGLMJPG 视频。

## 三、如何重新生成横屏视频

```bat
:: 拆包（仅当需要核对帧）可改用 unpack.py
python tools/video_rebuild/rebuild.py assets\video\video.bin out.bin --out 1920 480 --rotate 90
:: av093x 窄屏：横屏 1280x320
python tools/video_rebuild/rebuild.py source_480x1920.bin av093x.bin --out 1280 320 --rotate 90
```
> 工具依赖 Pillow。仓库自带 `tools/python/python3.exe` 未带 Pillow，可用 DSH 运行时 Python 或带 Pillow 的解释器运行。

## 四、需要上机核验的项（本改造无法在无硬件环境验证）

1. **旋转方向**：`display.c` 里 `MPP_ROTATION_90` 与重编码时 `--rotate 90` 的组合，若最终画面倒置/镜像，
   在 `0 / 90 / 270` 之间调整 `rotmir` 值即可（`--rotate` 也相应取反）。
2. **UI 窗口**：当前保持 400×480 居中浮层（内存约束），如需全屏横屏 UI 需补充 GE 硬件旋转（参考
   `lv_port_disp.c` 的 `LV_DISPLAY_ROTATE_GE_PARTIAL` 思路），并在 `ui.c` 中按物理扫描屏旋转 ARGB 输出。
3. **各面板比例**：各面板横屏目标分辨率 = `variants.json` 中宽/高互换：
   - txw935003b：1920×480　boe1126：1920×440　av092k5u：1920×462　cwd686：1280×480　av093x：1280×320
4. **空闲视频与 USB 帧分辨率**：host 端按横屏 `R<宽>x<高>` 发送 JPEG；空闲视频已重编码为横屏。
5. **内存**：fb 旋转下 `AIC_FB_ROTATE_EN` 会按 `fb_size*(1+AIC_FB_DRAW_BUF_NUM)` 分配，
   已在 PSRAM 预算内验证编译，但实际不同面板的 UI 尺寸/镜像需实测微调。
